## Decision Needed

| Question | Option | Impact IDs | Trade-off |
| --- | --- | --- | --- |
| When an offline mutation conflicts with server state, including a missing record after tombstone expiry, which authority policy should synchronization use? | Server-authoritative optimistic concurrency (recommended): send each mutation's last-seen updated_at, apply only when it still matches, surface stale edits as conflicts, never auto-resurrect missing records, and require full reconciliation before upload after more than 24 hours offline. | `IMP-001`, `IMP-002`, `IMP-003`, `IMP-004`, `IMP-005` | Best protection against lost remote updates and deletion resurrection, but needs conditional-write and reconciliation support and may require user conflict resolution. |
| When an offline mutation conflicts with server state, including a missing record after tombstone expiry, which authority policy should synchronization use? | Automatic last-write-wins: compare updated_at, let the later value win, let active tombstones win over older edits, and treat server absence as deletion after the tombstone window. | `IMP-001`, `IMP-002`, `IMP-003`, `IMP-004`, `IMP-005` | Simpler user experience, but correctness depends on trustworthy timestamp semantics and legitimate offline edits may be silently discarded. |
| When an offline mutation conflicts with server state, including a missing record after tombstone expiry, which authority policy should synchronization use? | Client replay wins: replay queued mutations in local creation order and recreate a missing record when necessary. | `IMP-001`, `IMP-002`, `IMP-003`, `IMP-004`, `IMP-005` | Maximizes preservation of offline work, but can overwrite newer server changes and resurrect intentionally deleted records. |
