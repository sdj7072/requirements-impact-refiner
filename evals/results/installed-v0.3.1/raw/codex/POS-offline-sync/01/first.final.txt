## Decision Needed

| Question | Option | Impact IDs | Trade-off |
| --- | --- | --- | --- |
| Which reconciliation policy should govern queued edits that meet newer server updates or deletions? | Optimistic concurrency with durable delete revisions (recommended): send each mutation’s base `updated_at`; apply only on a match; surface or merge conflicts; retain a compact delete revision beyond the 24-hour full-tombstone window. | `IMP-001`, `IMP-002`, `IMP-003` | Prevents silent overwrites and late resurrection while preserving the 24-hour full tombstone, but adds server metadata and conflict handling. |
| Which reconciliation policy should govern queued edits that meet newer server updates or deletions? | Server wins after refresh: discard queued edits to an existing record whenever its server version changed or it is now missing; replay explicitly local-only creations. | `IMP-001`, `IMP-002`, `IMP-003` | Avoids durable deletion metadata and is deterministic, but can silently lose offline user edits unless the UI preserves and explains rejected changes. |
| Which reconciliation policy should govern queued edits that meet newer server updates or deletions? | Timestamp last-write-wins: compare update and deletion times, with a retained tombstone winning while present. | `IMP-001`, `IMP-002`, `IMP-003` | Simple and mostly automatic, but clock authority must be defined and edits reconnecting after tombstone expiry can resurrect deleted records. |
