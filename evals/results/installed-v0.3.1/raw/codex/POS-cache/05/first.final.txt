## Decision Needed

| Question | Option | Impact IDs | Trade-off |
| --- | --- | --- | --- |
| Which invalidation policy should the one-hour dashboard cache use? | Invalidate affected tenant entries on `dashboard.updated` and invalidate or version affected entries on role changes (recommended). | `IMP-002`, `IMP-003`, `IMP-004` | Strongest freshness and permission safety; adds role-change wiring or an authorization-versioned key. |
| Which invalidation policy should the one-hour dashboard cache use? | Invalidate affected tenant entries on `dashboard.updated` only. | `IMP-002`, `IMP-003`, `IMP-004` | Uses the existing event, but role-sensitive output can stay stale unless authorization is reapplied on each hit. |
| Which invalidation policy should the one-hour dashboard cache use? | Use TTL-only expiry. | `IMP-002`, `IMP-003`, `IMP-004` | Simplest, but writes and role changes can leave results stale for one hour. |
