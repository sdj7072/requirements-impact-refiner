## Decision Needed

| Question | Option | Impact IDs | Trade-off |
| --- | --- | --- | --- |
| Which events may end a “permanent” shared link? | Link-scoped permanence: it survives time, permission changes, and key rotations; only explicit revocation of that link or deletion of the resource ends access. | `IMP-001`, `IMP-002`, `IMP-003`, `IMP-004`, `IMP-006` | Strongest link durability, but anyone retaining the URL keeps access after later permission loss until the link itself is revoked. |
| Which events may end a “permanent” shared link? | Authorization-bound permanence: it has no age expiry and survives key rotations, but permission loss, explicit revocation, or resource deletion ends access. | `IMP-001`, `IMP-002`, `IMP-003`, `IMP-004`, `IMP-006` | Preserves current authorization revocation semantics, but the link is not permanent across permission changes. |
| Which events may end a “permanent” shared link? | Immutable link: it survives time, permission changes, key rotations, and ordinary revocation; only an exceptional security shutdown ends access. | `IMP-001`, `IMP-002`, `IMP-003`, `IMP-004`, `IMP-006` | Literal permanence, with the highest disclosure, deletion, and incident-response risk. |
