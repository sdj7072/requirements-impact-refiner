## Decision Needed

| Question | Option | Impact IDs | Trade-off |
| --- | --- | --- | --- |
| Which revocation contract should “permanent” shared links use? | A — Durable but revocable (recommended): time and key rotation never invalidate a link, while permission changes and explicit revocation still do. | IMP-001, IMP-002, IMP-003, IMP-004 | Preserves authorization and incident response; “permanent” means no scheduled expiry, not irrevocable. |
| Which revocation contract should “permanent” shared links use? | B — Explicit-revocation only: time, key rotation, and permission changes do not invalidate a link; only revoking that specific link does. | IMP-001, IMP-002, IMP-003, IMP-004 | Link holders retain access after source permissions change; reliable per-link revocation and auditing become essential. |
| Which revocation contract should “permanent” shared links use? | C — Immutable: no expiry or revocation, including after permission changes or key rotation. | IMP-001, IMP-002, IMP-003, IMP-004 | Maximizes permanence but prevents containment of leaked links and conflicts with current permission revocation. |
