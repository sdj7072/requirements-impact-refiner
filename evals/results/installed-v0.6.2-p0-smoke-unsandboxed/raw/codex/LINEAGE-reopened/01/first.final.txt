## Change Impact Summary

### Impact IMP-001

- Changed feature: profile.displayName is removed from mobile profile decoding.
- Possible issue: A released client that still decodes displayName could receive payloads without the field before its compatibility window ends.
- Affected feature or user: Mobile clients using ProfileDecoder.decodeDisplayName during the migration window.
- Trigger: Server-side removal of profile.displayName while a client release that expects it is still active.
- Severity: high
- Prevention or check: Preserve profile.displayName for one release and verify release ordering before completing removal.
- Status: mitigated

### Impact IMP-002

- Changed feature: The profile.displayName field enters a one-release removal migration.
- Possible issue: Removing the stored or serialized field too early could discard data still needed by clients in the compatibility window.
- Affected feature or user: Profile records and payload serialization for profile.displayName.
- Trigger: Migration cleanup runs before the configured preservation release has elapsed.
- Severity: medium
- Prevention or check: Keep PRESERVE_RELEASES at 1 and verify cleanup occurs only after that release boundary.
- Status: mitigated

### Impact IMP-003

- Changed feature: decodeDisplayName no longer supplies a display-name value from profile payloads.
- Possible issue: Profile UI or client logic may continue to expect a decoded display name.
- Affected feature or user: Potential mobile code paths downstream of ProfileDecoder.decodeDisplayName.
- Trigger: The decoder field is removed while a downstream caller still relies on its returned value.
- Severity: medium
- Prevention or check: Remove or adapt downstream use and verify profile behavior with payloads that omit displayName.
- Status: detected
