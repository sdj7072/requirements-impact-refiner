## Change Impact Summary

### Impact IMP-001

- Changed feature: authorization.workspace_edit admits the member role.
- Possible issue: Every workspace member gains edit authority over every project, broadening write access beyond owners and admins.
- Affected feature or user: All projects and users assigned the workspace member role, including invitation-default users.
- Trigger: authorize_project_edit evaluates role member.
- Severity: critical
- Prevention or check: Implement only the explicitly selected role widening, retain existing roles, deny unrecognized roles, and cover the boundary with authorization tests.
- Status: accepted

### Impact IMP-002

- Changed feature: Member-authorized project edits enter the existing edit/audit behavior.
- Possible issue: A newly authorized member edit could bypass or lose actor-role audit attribution if downstream code special-cases privileged roles.
- Affected feature or user: Audit consumers and operators investigating project edits.
- Trigger: A member performs an authorized project edit.
- Severity: high
- Prevention or check: Preserve emit_actor_role_audit behavior and verify a member edit produces project.edit.audited with the member actor and role.
- Status: mitigated

### Impact IMP-003

- Changed feature: The permitted-role set gains member.
- Possible issue: A broader or replacement edit could accidentally remove owner/admin access or authorize roles other than member.
- Affected feature or user: Existing owners and admins, plus callers passing unsupported roles.
- Trigger: The permission set is changed.
- Severity: high
- Prevention or check: Append member to the existing permitted roles and test positive and negative role cases.
- Status: mitigated
