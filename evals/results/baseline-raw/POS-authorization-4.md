# Authorization impact: workspace members can edit every project

## Requirement

Allow every workspace member to edit every project in that workspace.

## Current behavior

- `authorizeProjectEdit` permits only workspace owners and admins.
- Workspace invitations default to the `member` role.
- Project edits emit an audit event containing the actor’s role.

## Required authorization change

Extend `authorizeProjectEdit` so that the `member` role is authorized for project edits. Existing owner and admin access must remain unchanged. The authorization decision should continue to be scoped to workspace membership and the relevant project; this requirement does not imply access for users who are not members of the workspace.

Because invitations already default to `member`, newly invited users should gain project-edit capability once their membership is active, without a separate invitation-flow change.

## Audit implications

Keep emitting the existing project-edit audit event. Ensure events generated by members record `member` as the actor role, while owner and admin edits continue to record their actual roles. Audit consumers, filters, and reports that assume only owner/admin actors may need to accept and display member-originated edits.

## Acceptance criteria

1. An active workspace member can edit any project in that workspace.
2. Owners and admins retain their existing edit access.
3. Non-members cannot edit the workspace’s projects.
4. An active invited member (whose invitation defaults to `member`) can edit after joining.
5. Every project edit produces an audit event with the correct actor identity and role, including `member`.
6. Tests cover member authorization, unchanged owner/admin behavior, non-member denial, and audit-role recording.

## Out of scope / risks

This broadens write access across all projects and may expose project content or enable destructive changes to ordinary members. Project-level exceptions, approval workflows, and finer-grained permissions are not specified and should not be inferred. Review downstream audit and notification behavior for assumptions about the previous role set.
