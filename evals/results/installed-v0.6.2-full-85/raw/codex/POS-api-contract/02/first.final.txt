## Decision Needed

- Question: How should the rename handle the existing consumers and the one-release deprecation policy?

### Option 1

- Option: Stage the rename for one release
- Affected impacts: IMP-001, IMP-002, IMP-003
- Trade-off: Publish profile.name while retaining profile.displayName for one release; update consumers and cache compatibility now, then remove the old field later.

### Option 2

- Option: Coordinate an immediate breaking rename
- Affected impacts: IMP-001, IMP-002, IMP-003
- Trade-off: Update the API, iOS decoder, and cache key together now, but make this a breaking release and explicitly waive the one-release policy.

### Option 3

- Option: Change only api/profile.py
- Affected impacts: IMP-001, IMP-002, IMP-003
- Trade-off: Matches the narrow file request, but knowingly breaks the current decoder/cache contract and violates the declared deprecation window.
