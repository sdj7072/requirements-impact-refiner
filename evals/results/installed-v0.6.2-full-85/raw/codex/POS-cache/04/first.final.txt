## Change Impact Summary

### Impact IMP-001

- Changed feature: Tenant dashboard responses are cached for one hour.
- Possible issue: A user could receive a dashboard response based on permissions that were revoked or changed.
- Affected feature or user: Users whose tenant roles change while a cached dashboard response exists.
- Trigger: Role-change invalidation of permission_cache.
- Severity: critical
- Prevention or check: Invalidate the corresponding tenant dashboard cache entry as part of the role-change path.
- Status: mitigated

### Impact IMP-002

- Changed feature: Dashboard responses may be served from cache for one hour.
- Possible issue: Dashboard changes may remain invisible until TTL expiry.
- Affected feature or user: Tenants with a cached response when dashboard.updated is published.
- Trigger: Publication of dashboard.updated.
- Severity: high
- Prevention or check: Evict the affected tenant dashboard cache entry when the update event is handled.
- Status: mitigated

### Impact IMP-003

- Changed feature: Rendered dashboard responses are reused across requests.
- Possible issue: An insufficient cache key could return one tenant's response to another tenant.
- Affected feature or user: All dashboard tenants.
- Trigger: A cache lookup for tenants with colliding or shared keys.
- Severity: critical
- Prevention or check: Use tenant_id as the complete cache identity and test isolation explicitly.
- Status: mitigated

### Impact IMP-004

- Changed feature: Repeated renders for a tenant reuse a cached response.
- Possible issue: Incorrect expiry semantics could cache forever or miss the requested performance benefit.
- Affected feature or user: All dashboard callers.
- Trigger: Repeated calls before and after the one-hour boundary.
- Severity: medium
- Prevention or check: Use a monotonic expiry of 3,600 seconds and test hit and expiry behavior.
- Status: mitigated
