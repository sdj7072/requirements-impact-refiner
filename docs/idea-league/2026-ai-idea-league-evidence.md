# 2026 SK AI Idea 리그 증빙 부록

이 문서는 제출 본문의 수치와 표현을 검증하기 위한 내부 작업 자료입니다. 실제 현업 생산성 측정값과 통제 평가 결과를 혼동하지 않기 위해, 모든 수치를 근거 파일과 함께 기록합니다.

## 1. 측정 범위

- 실제 사용자 수, 사용 횟수, 시간·비용 절감: **측정하지 않음**
- 통제 평가: 저장소에 보존된 baseline 및 with-skill AI 응답을 사전 정의된 기준으로 채점
- 제품 상태: `0.4.0` Public Preview
- 평가 결과의 의미: 특정 기록 환경에서 관찰한 품질 대리 지표이며 다른 모델·클라이언트·업무 환경의 성과를 보장하지 않음

## 2. 제출에 사용할 수 있는 전후 비교

### 2.1 결제 변경의 근거 연결

대상 위험은 다음 세 가지입니다.

1. 기존 요청이 제공하는 idempotency key
2. webhook 확정 전에 사용자에게 보이는 결제 상태
3. 결제 완료 후 timeout이 발생할 때의 중복 청구 위험

| 구성 | 엄격한 근거 연결 | 전체 기회 | 비율 |
| --- | ---: | ---: | ---: |
| 스킬 미적용 baseline | 8 | 15 | 53.3% |
| RIR 적용 rerun 5 | 15 | 15 | 100% |
| 차이 | +7 | - | +46.7%p |

근거:

- baseline: `evals/results/baseline.md`의 Results 및 Demonstrated Failures
- RIR 적용: `evals/results/with-skill-raw/scoring/green-rerun5-scoring.md`의 Aggregate checks

주의: baseline에서도 위험 주제 자체를 언급한 응답은 있었습니다. 8/15는 주제 언급률이 아니라 제공된 저장소 사실과 엄격하게 연결한 탐지 수입니다.

## 3. 대표 재현 시나리오

### 입력

```text
계획 전에 프로필 API의 displayName을 name으로 변경할 때 API, iOS DTO,
저장된 캐시 경로에 미치는 영향을 정제해 줘. 기존 클라이언트는 한 버전
동안 호환되어야 해.
```

### 기존 방식에서 빠질 수 있는 질문

- 현재 iOS DTO가 어떤 키를 디코딩하는가?
- 이미 저장된 캐시 JSON은 앱 업데이트 후에도 읽히는가?
- 한 버전 호환 약속은 필드 병행, alias, migration 중 무엇을 뜻하는가?
- 사용자가 정책을 선택하기 전에 AI가 임의의 전환 방식을 확정하지 않았는가?

### RIR이 만드는 검토 구조

- `INV`: 기존 iOS 릴리스는 `displayName`을 디코딩함
- `IMP`: 모바일 디코딩 실패 가능성
- `IMP`: 저장된 캐시 페이로드 호환성
- `IMP`: 외부 소비자 미확인 영역
- 결정 선택지: 즉시 변경 / 두 필드 병행 / 명시적 마이그레이션
- `AC`: 기존 디코더와 캐시 fixture의 회귀 기준

대표 예시는 `README.ko.md`의 4절과 `docs/compact-delivery-demo.md`에서 재현할 수 있습니다.

## 4. 표현 가이드

사용 가능:

- “통제 평가에서 8/15에서 15/15로 개선됐다.”
- “실제 현업 시간 절감은 아직 측정하지 않았다.”
- “알려진 실패 1건을 포함해 24/25를 기록했다.”
- “다른 환경의 지원을 의미하지 않으며 Public Preview 상태다.”

사용 금지:

- “업무 시간이 N% 단축됐다.”
- “버그를 100% 예방한다.”
- “모든 Codex·Claude 환경에서 검증됐다.”
- “85/85이므로 완전한 제품이다.”
- `blocked` 또는 `not verified` 환경을 지원 환경으로 표현
